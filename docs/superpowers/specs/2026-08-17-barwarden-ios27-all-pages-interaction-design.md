# Barwarden 全应用 iOS 27 UI 与交互统一设计

日期：2026-08-17
状态：已批准方向，待实施计划
目标平台：macOS 菜单栏原生 Tauri 窗口，固定基准视口 480 × 600

## 1. 背景

Barwarden 当前已经在密码库首页建立了第一批 iOS 27 视觉基础：冷蓝画布、语义动作色、44 × 44 命中区、连续列表和搜索优先。其余页面仍混合使用 Bitwarden Web 表单、独立卡片、重边框、胶囊控件和不一致的弹层样式，导致同一应用在页面切换后视觉密度、层级和操作反馈发生明显变化。

本设计把已定稿的密码库首页语言扩展到全部用户可见页面和状态，并同时统一交互行为。它不是单纯换色或覆盖 CSS，而是以共享页面壳、连续列表、表单组、反馈状态和弹层契约为基础，逐个页面族迁移。

## 2. 已选视觉来源

- 主视觉目标：`docs/superpowers/specs/assets/barwarden-ios27-ui-visual-target.png`。
- 当前应用结构参考：`docs/ui-audit-2026-08-17/01-login.png` 至 `10-vault-dark.png`。
- 已实现基线：密码库首页浅色、搜索和深色 480 × 600 原生截图。
- 视觉原则：扁平、简约、冷蓝通透、低噪声、连续表面、清晰语义色。

已有 Bitwarden 图标字体和官方组件继续作为图标与行为来源，不创建自绘图标、CSS 图形或替代资产。

## 3. 用户目标

用户应能在任何页面快速理解当前层级、找到主操作、通过键盘或鼠标完成任务，并在加载、失败、保存或危险操作时获得一致反馈。页面切换不应让用户重新学习布局、按钮优先级或返回方式。

## 4. 范围

### 4.1 页面族

1. 认证与账户：登录、环境选择、自托管配置、锁定、PIN/生物识别替代解锁、密码提示、两步验证、新设备验证、账户切换。
2. 主导航：密码库、OTP、生成器、Send、设置，以及固定底部导航和通用标题栏。
3. 密码库工作流：列表、搜索、筛选、自动填充建议、详情、添加、编辑、克隆、密码历史、文件夹、归档、回收站、新建项目菜单和安全重提示。
4. 生成器与 Send：生成器结果与选项、历史记录、Send 列表、详情、创建/编辑、创建成功和错误状态。
5. 设置与信息：设置首页、密码库设置、账户安全、设置密码、自动填充、快捷键、外观、关于、更新、第三方声明与许可证。
6. 全局覆盖层：菜单、Sheet、确认框、危险操作弹窗、权限弹窗、反馈条、空态、加载态和错误态。

### 4.2 状态

覆盖浅色、深色、跟随系统、紧凑模式、加载、空、无结果、离线、失败、重试、保存中、禁用、长文本、键盘焦点、菜单打开、表单无效和危险确认。现有 evidence states 继续作为确定性验收入口。

### 4.3 非目标

- 不改变认证、安全重提示、候选排序、自动填充、安全存储或数据同步规则。
- 不新增路由或重写业务服务。
- 不替换 Bitwarden 官方组件体系和图标库。
- 不为了视觉统一移除用户已批准的用户名、密码、验证码快捷操作。
- 不将普通内容模拟成 Sheet；只有真实覆盖层保留浮层形状。

## 5. 方案

采用“共享组件优先，按页面族迁移”。先完成稳定的视觉与交互原语，再让所有页面显式加入对应页面族 class 和组件契约。禁止依靠无边界的全局选择器一次性压平所有官方组件。

### 5.1 共享层

共享层由以下原语组成：

- 页面壳：统一画布、可滚动内容区、安全底部留白和固定导航。
- 页面标题栏：返回、居中标题、副标题和最多两个显性操作。
- 连续分组：分组标题、连续行、inset 分隔线、首尾规则和空组处理。
- 表单组：标签、说明、输入、选择器、开关、错误信息和帮助动作。
- 操作体系：主按钮、次按钮、文字按钮、透明图标按钮和危险动作。
- 反馈体系：骨架屏、空态、内联错误、全页错误、成功反馈和重试。
- 覆盖层：菜单、Sheet、确认框和危险确认。

页面族可以调整内容密度，但不能重新定义圆角、阴影、行高、焦点环或按钮优先级。

## 6. 全局视觉系统

### 6.1 表面与层级

- 每个页面只有一个主画布，普通内容不使用独立悬浮卡片。
- 连续组使用轻微表面色差和细分隔线表达结构，不使用阴影。
- 搜索、输入、分段选择器和真正的覆盖层可以拥有独立形状。
- 菜单、Sheet、确认框和危险弹窗使用 12–16 px 圆角与单层轻阴影。
- 深色模式使用明确的实色 navy 表面阶梯，避免多个透明层叠加成灰雾。

### 6.2 尺寸

- 页面水平边距：16 px。
- 组间距：20–24 px。
- 标准行高：52 px；紧凑辅助行最低 44 px。
- 所有可点击图标和开关命中区：至少 44 × 44 px。
- 搜索和表单控件圆角：10–12 px。
- 组内部行不使用 4–8 px 卡片间隙。

### 6.3 字体与颜色

- 页面标题：18–20 px，650–700。
- 组标题和主行标题：14–15 px，600 左右。
- 正文：14–15 px；次级信息：12–13 px。
- 主强调使用蓝色；用户名、密码、验证码继续使用蓝、靛、橙语义色。
- 危险操作使用红色文字或红色轻背景，不与主操作同权并排。
- 页面不得自行硬编码灰白背景、黑色阴影或新的强调色。

## 7. 全局交互契约

### 7.1 导航与状态恢复

- 主标签页保留各自滚动位置和搜索/筛选状态；返回详情后恢复原列表位置。
- 二级页统一使用左上返回按钮，返回后恢复发起控件焦点。
- 底部导航只出现在五个主标签页；表单、详情和确认流程不重复显示。
- 新窗口打开、账户菜单和新增操作在相同页面类型中保持固定位置。

### 7.2 键盘与焦点

- Tab 顺序遵循视觉阅读顺序；不可见和禁用控件不进入顺序。
- Enter 触发当前表单主操作；Escape 依次关闭菜单、Sheet 或返回上一层。
- 菜单和 Sheet 打开时焦点进入内部，关闭后回到触发器。
- 所有键盘可操作元素使用统一 2 px 焦点环，不依赖颜色或动画单独表达状态。

### 7.3 列表动作

- 密码库登录项继续根据真实能力显示用户名、密码和验证码快捷操作；不伪造缺失字段。
- 快捷动作与行导航隔离，点击复制/填入不得同时打开详情。
- 非凭据列表行默认显示一个最主要操作和“更多”；危险动作进入菜单或独立危险区。
- 行 hover、pressed、focused 和 menu-open 使用同一组选中表面规则。

### 7.4 表单

- 输入在 blur 后显示字段级错误；提交时显示全部阻塞错误并聚焦首个错误。
- 保存中锁定重复提交，但允许用户阅读当前值；按钮显示明确进行中状态。
- 失败保留用户输入并提供原位重试，不自动清空或跳离页面。
- 离开有未保存更改的表单时使用统一确认 Sheet。
- 密码、验证码和敏感字段沿用既有显示、复制、生成与重提示安全边界。

### 7.5 异步反馈

- 首次加载使用与最终布局同构的骨架屏，避免内容跳动。
- 局部刷新保留现有内容并显示轻量进行中状态。
- 成功反馈使用短暂非阻塞反馈条；错误优先内联显示在相关区域。
- 全页不可用状态包含原因、恢复建议和唯一主重试操作。

### 7.6 动效

- 标准时长 150–220 ms，只使用轻微淡入、位移和展开。
- 禁止大幅弹跳、缩放和持续装饰动画。
- `prefers-reduced-motion` 下取消非必要过渡，状态变化仍需立即可见。

## 8. 页面族设计

### 8.1 认证与账户

- 取消登录卡套页面卡，表单直接位于单一画布中。
- 环境作为表单底部的次级选择行；自托管配置继续使用 Sheet。
- 登录、锁定、两步验证和新设备验证共享标题、表单组、错误与主按钮位置。
- 替代解锁选项按优先级组成连续列表，不使用多个同权大按钮。
- 账户切换使用连续账户行；当前账户、锁定和错误状态均有明确文本，而非只靠图标。

### 8.2 主导航与密码库首页

- 延续已通过的密码库首页设计：搜索在标题下方，自动填充建议紧随搜索，主动搜索时建议隐藏。
- 五个主标签页共享标题栏和底部导航高度、选中态和安全间距。
- OTP 列表使用连续行，验证码本身保持高可读与一键复制。
- 搜索、筛选和展开状态使用可预测的清除/折叠动作，并恢复焦点。

### 8.3 密码库详情、表单与恢复

- 详情页去除标题卡、字段卡和底栏三重容器；标题并入页面标题栏，字段按连续分组排列。
- 字段动作保持 44 px 命中区；常用复制/显示动作显性，低频动作进入更多。
- 添加、编辑和克隆共享表单组；底部主次动作保持稳定，不随字段数量漂移。
- 文件夹、归档、回收站和密码历史复用连续列表与统一空态。
- 永久删除和敏感重提示保持真实圆角确认层，并明确对象和不可逆后果。

### 8.4 生成器与 Send

- 生成结果固定在内容顶部，复制为主动作；类型选择使用单一分段控件。
- 长选项区拆成连续设置组；布尔项使用开关，数值使用滑杆配合明确数值。
- 生成历史使用连续行和统一清空确认。
- Send 列表、详情、表单和成功页共享页面壳；成功页强调可复制链接和下一步，不使用大面积庆祝卡。
- Send 禁用、无结果和操作失败均使用统一反馈体系。

### 8.5 设置与信息页

- 设置首页按通用、安全、应用和信息组织连续分组。
- 所有布尔项使用系统式开关；单选/主题/语言使用选择行或分段控件。
- 设置详情页共享标题、说明、连续表单组和保存反馈。
- 关于、更新、第三方声明和许可证使用安静的文档布局；长文本保留清晰标题层级和滚动位置，不套卡片。

### 8.6 覆盖层

- Sheet、菜单和确认框是唯一允许浮层圆角与阴影的内容。
- Sheet 使用紧凑标题、16 px 内容边距和对齐的主次按钮。
- 危险确认必须说明对象、后果和危险主按钮；取消保持默认焦点。
- 权限请求解释用途并提供前往系统设置的明确动作，不用泛化错误文案。

## 9. 数据与业务边界

视觉组件只消费现有页面状态和命令，不拥有认证、同步、自动填充或加密逻辑。页面迁移应保留现有事件、路由参数、guard、重提示和失败恢复路径。共享组件通过输入输出表达状态，不直接调用业务服务。

对上游 retained overlay 的模板修改继续由 hash guard 锁定；每次显式改动后必须审查并更新对应锁值，不能绕过 guard。

## 10. 错误处理

- 字段错误：紧邻字段并通过可访问描述关联。
- 区域错误：显示在相关连续组顶部，保留可操作内容。
- 页面错误：占据内容区但保留标题栏和返回路径。
- 操作错误：不关闭当前菜单/Sheet 造成上下文丢失，除非安全流程要求关闭。
- 离线与陈旧数据：明确标识数据状态并提供同步/重试。

## 11. 可访问性

- 关键命中区至少 44 × 44 px。
- 保留语义标题、导航、列表、菜单、对话框和状态播报。
- 颜色不能是唯一状态提示；选中、错误和危险均有图标或文字。
- 长文本和 200% 缩放下不能发生水平滚动或遮挡主操作。
- 验证键盘完整路径、焦点恢复、Escape 关闭顺序、VoiceOver 名称与动态状态播报。
- 深色、高对比度、降低透明度和减少动态效果分别验收。

## 12. 实施分批

1. 共享页面壳、标题栏、连续组、表单、动作、反馈和覆盖层规则。
2. 设置与信息页，建立连续设置组范式。
3. 认证与账户页，统一表单和验证反馈。
4. 密码库详情、表单、OTP、恢复页。
5. 生成器和生成历史。
6. Send 列表、详情、表单和成功页。
7. 全局交互、键盘、动效、深色和可访问性收口。
8. 全路由视觉回归、原生截图比较和最终整段审查。

每批先添加组件行为或 computed-style 测试，确认失败后实施最小改动；通过聚焦测试、构建和审查后再进入下一批。

## 13. 验证与完成标准

- 所有生产路由均显式归属页面族，不存在未覆盖的旧卡片式页面。
- 所有主流程在 480 × 600 原生窗口可完成，主操作不被底部导航遮挡。
- 浅色、深色和跟随系统的页面层级与语义色一致。
- 列表、表单、菜单、Sheet、确认框、空态、加载态和错误态遵循共享契约。
- 用户名、密码、验证码快捷操作按真实能力保留，且与行导航隔离。
- 键盘、焦点恢复、减少动态效果和危险确认通过行为测试。
- 完整自动化测试和 Web 构建通过。
- 每个页面族至少选择一个代表性页面和关键状态，在同一比较输入中与设计目标或审计参考进行 480 × 600 原生视觉 QA。
- 根目录 `design-qa.md` 最终写明 `final result: passed`，且不存在 P0/P1/P2 视觉问题。
