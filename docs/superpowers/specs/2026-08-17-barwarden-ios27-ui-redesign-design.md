# Barwarden 扁平化 iOS 27 UI 优化设计

日期：2026-08-17
状态：视觉方向已由用户确认，等待书面规格复核
目标窗口：480 × 600 菜单栏窗口，并兼容独立弹出窗口

## 1. 目标

把当前混合了 Web 表单、macOS 材质和移动端卡片的界面，收束为安静、清透、扁平的系统面板体验。用户打开窗口后应能优先完成三件事：搜索凭据、使用自动填充建议、对登录条目快速操作用户名/密码/验证码。

成功标准：

- 窗口只呈现一个主材质层；普通内容不再依赖卡片、阴影和重复边框建立层级。
- 搜索、自动填充建议和普通项目形成明确的纵向顺序。
- 每个登录类条目在字段存在时保留用户名、密码和 TOTP 三个快捷操作。
- 视觉图标保持 18–20 px，但所有可点击图标的命中区域不小于 44 × 44 px。
- 浅色、深色、增加对比度、降低透明度和减少动态效果均可用。
- 不改变密码库、同步、原生自动填充和安全校验的业务语义。

## 2. 设计依据

- UI 审计：`docs/ui-audit-2026-08-17/README.md`
- 用户提供的自动填充建议参考图：强调连续列表和每行三个快捷操作。
- 已确认视觉目标：`docs/superpowers/specs/assets/barwarden-ios27-ui-visual-target.png`
- 现有界面基础：Angular 官方组件适配层、macOS tokens、52 px 列表行和现有自动填充候选服务。

视觉目标图用于约束层级、密度、色彩和图标表达；其中演示数据不定义业务能力。非登录条目不显示不存在的用户名、密码或 TOTP 操作。

## 3. 已选择的方向

采用“搜索优先的连续系统表面”。顶部保留紧凑标题与少量全局操作，搜索框独立成形；自动填充建议紧接搜索；普通项目继续向下排列。列表行不做独立卡片，使用留白、字体、微弱表面色差和细分隔线组织内容。

未采用的方向：

- 卡片式分区：识别度高，但在 480 × 600 中产生过多容器和留白。
- 密集工具台：筛选胶囊、结果数量和方框图标同时出现时，搜索与建议失去主次。
- 单一复制按钮：操作更简洁，但不满足用户名、密码和验证码的直接访问要求。

## 4. 视觉系统

### 4.1 浅色主题

| 语义 | 颜色 | 用途 |
| --- | --- | --- |
| 窗口背景 | `#F4F8FF` | 主画布与页面底色 |
| 主内容表面 | `#FBFDFF` | 连续列表和主体内容 |
| 上下文浅色面 | `#EAF2FF` | 搜索框、自动填充建议的轻微区分 |
| 主文字 | `#111827` | 标题与主要内容 |
| 次级文字 | `#536784` | 用户名、说明和辅助信息 |
| 分隔线 | `#D4E1F2` | 1 px 行分隔与组边界 |
| 主强调色 | `#0A66FF` | 当前导航、焦点、主要交互 |
| 用户名动作 | `#0A66FF` | 用户图标 |
| 密码动作 | `#6657D9` | 钥匙图标 |
| TOTP 动作 | `#E98A15` | 时钟图标 |
| 通用网站类型 | `#2196C9` | 地球等站点类型图标 |
| 卡片类型 | `#159A8A` | 银行卡等非登录类型图标 |

颜色只落在图标字形和必要的状态反馈上。快捷操作不增加常驻圆形、方形或描边底框。

### 4.2 深色主题

| 语义 | 颜色 |
| --- | --- |
| 窗口背景 | `#101621` |
| 主内容表面 | `#151D2A` |
| 上下文浅色面 | `#1A2638` |
| 主文字 | `#F4F7FB` |
| 次级文字 | `#A9B7CC` |
| 分隔线 | `rgb(197 216 241 / 18%)` |
| 主强调色/用户名 | `#4C8DFF` |
| 密码 | `#9B8CFF` |
| TOTP | `#FFB454` |
| 网站类型 | `#5CC8E8` |
| 卡片类型 | `#43CDBA` |

深色模式使用实色阶梯建立层级，不依赖多层透明叠加。增加对比度或降低透明度时，材质退化为这些实色表面。

### 4.3 尺寸、圆角与阴影

- 页面水平边距：16 px。
- 标题区：48–52 px；页面标题 18–20 px、650–700 字重。
- 搜索框：44 px 高，12 px 圆角。
- 普通行：52 px；需要两行文本时可增至 56 px，但同组保持一致。
- 图标：18–20 px；交互命中区域至少 44 × 44 px。
- 组间距：20–24 px；行内左右间距：12–16 px。
- 普通列表、设置组和字段组不使用阴影。
- 仅菜单、Sheet 和底部导航允许一层轻阴影；不出现卡片套卡片。

## 5. 保险库主页

页面顺序固定为：

1. 紧凑标题栏：标题、添加、弹出窗口和账户入口。
2. 搜索框。
3. 自动填充建议；仅在存在上下文候选且搜索为空时显示。
4. 普通密码库层级或搜索结果。
5. 底部导航。

### 5.1 搜索行为

- 搜索为空时，自动填充建议按上下文出现并默认展开。
- 用户输入第一个非空字符后，自动填充建议从布局中隐藏，搜索结果成为唯一主内容。
- 清空搜索后，如果上下文候选仍有效，建议区重新出现并默认展开。
- 搜索框不附加筛选胶囊和结果数量控件；结果数量可由分组标题或读屏状态表达。
- 无结果、加载、同步过期和不可用状态沿用现有业务判断，但改用同一连续表面语言。

### 5.2 自动填充建议

- 建议区直接位于搜索框下方，不包裹成独立浮动卡片。
- 分组标题显示“自动填充建议 (N)”和展开/收起图标。
- 最多显示现有候选策略允许的数量，不在 UI 层重新排序或改变匹配规则。
- 每行左侧为条目类型/站点图标，中间为名称与用户名，右侧为快捷操作。
- 点击主体打开详情；点击快捷操作只执行对应字段动作，不触发行主体。
- 忙碌、重提示、域名不匹配确认、复制反馈和失败恢复继续使用现有服务与安全流程。

### 5.3 快捷操作

- 登录条目在对应字段存在时显示：用户名、密码、TOTP。
- 三个动作的顺序始终为用户名 → 密码 → TOTP。
- 图标采用已确认的语义色：蓝 → 靛紫 → 暖橙。
- 不存在的字段不伪造操作，也不使用不可解释的空按钮占位。
- 非登录类型只显示该类型真实支持的动作；更多管理操作留在详情或更多菜单。
- 图标按钮必须具有可访问名称、键盘焦点、忙碌/禁用状态和复制/填充结果反馈。

### 5.4 普通列表与搜索结果

- 采用连续列表和 inset 分隔线，不为每条结果创建独立卡片。
- 登录类普通列表遵循同一快捷操作规则；设置关闭快捷操作时保持现有用户偏好。
- 悬停、键盘聚焦和按下状态使用轻微底色变化，不改变行尺寸。
- 站点图标优先使用真实 favicon；没有 favicon 时使用现有类型图标库，不绘制自定义 SVG。

## 6. 全应用一致性

本轮优化覆盖审计中的现有界面，但不增加新页面或新业务功能。

### 6.1 登录与环境选择

- 移除“页面背景 + 外层白卡 + 输入框 + 环境胶囊”的重复层级。
- 表单直接落在主表面，环境选择作为紧凑次要行。
- 主按钮保持唯一主操作，宽度和高度不过度抢占页面。

### 6.2 Sheet 与菜单

- 自托管配置、确认和更多菜单保留真正的浮层语义。
- Sheet 统一 16 px 水平边距、紧凑标题区和清晰主次按钮。
- 菜单仅使用一层轻材质与轻阴影，不叠加触发器胶囊阴影。

### 6.3 条目详情

- 标题合并到页面导航区域，不再单独占用大卡片。
- 字段使用连续分组列表；复制、显示和填入动作保持 44 px 命中区域。
- 编辑是主要管理动作；归档和删除进入独立危险区或更多菜单，不与主要操作同权并排。

### 6.4 生成器

- 结果保持顶部优先，可直接复制。
- 密码/用户名/口令模式使用一个连续分段控件。
- 参数改为系统式连续设置组；长度采用滑杆与数值的组合，不重复大容器。
- 底部内容预留导航高度，最后一项不被导航遮挡。

### 6.5 设置与外观

- 按“通用 / 安全 / 应用”等语义形成连续分组列表。
- 布尔项使用开关；语言、主题等枚举项使用选择行。
- 每组可有一个容器轮廓，但组内行不再各自成卡。

## 7. 组件与实现边界

### 7.1 复用现有组件

- 继续使用 `popup-page`、`popup-header`、`bw-root-search`、`bit-item`、`bit-item-group`、`bitIconButton`、现有 Sheet 和底部导航。
- 通过 `macos-tokens.css` 和共享样式建立色彩、表面、分隔线、命中区域与状态规则。
- 通过现有列表、分组和官方图标适配层实现，不引入新的 UI 框架或自绘图标系统。

### 7.2 允许的结构调整

- 保险库主页可根据搜索状态控制上下文建议区是否渲染。
- 自动填充建议组件可增加明确的搜索可见性输入，但候选数据、排序、匹配和安全确认仍由现有服务负责。
- 页面模板可减少多余容器和卡片 class；共享视觉逻辑优先落到 tokens 和基础组件，避免页面级重复 CSS。

### 7.3 不在本轮改变

- 密码库数据结构、加密与解密流程。
- 候选匹配算法、候选数量契约和原生自动填充通信协议。
- 同步、登录、重提示和域名不匹配的业务规则。
- 路由、导航信息架构和设置项集合。

## 8. 状态、反馈与错误处理

- 加载使用现有骨架屏，但形状与最终连续列表一致，避免卡片跳变。
- 复制或填入成功使用轻量就地反馈和读屏播报，不弹出阻塞对话框。
- 用户主动操作失败时保留当前内容和可重试入口；后台失败不抢占主任务。
- 域名不匹配、重提示和危险操作继续使用 Sheet/对话框，因为它们需要明确确认。
- 禁用状态同时使用透明度、颜色和 `disabled` 语义，不只依赖颜色。

## 9. 动效与可访问性

- 展开/收起、按下和页面内容切换控制在 150–220 ms。
- 动效只用于说明状态变化，不用于持续装饰。
- `prefers-reduced-motion` 下移除位移，只保留必要的瞬时或淡化反馈。
- 所有文字和关键图标满足 WCAG AA；增加对比度模式提高分隔线、次级文字和焦点环的对比。
- 键盘顺序遵循视觉顺序：搜索 → 建议标题 → 建议行主体及快捷操作 → 普通列表 → 底部导航。
- 焦点环不能被圆角容器或滚动区域裁切。
- 快捷图标的可访问名称必须包含条目和字段，例如“复制 OpenAI 的密码”。

## 10. 验证与验收

### 10.1 自动测试

- 组件测试覆盖：搜索为空时显示建议、输入搜索后隐藏建议、清空后恢复建议。
- 组件测试覆盖：用户名/密码/TOTP 按字段能力显示，顺序固定，点击不会触发行主体。
- 回归测试覆盖：快捷操作关闭偏好、忙碌禁用、重提示、域名不匹配和操作失败。
- 视觉测试覆盖 480 × 600 的浅色、深色、搜索结果、无结果、详情、生成器、设置和登录状态。

### 10.2 人工验收

- 与视觉目标图在相同 480 × 600 视口并排比较；重点检查层级、密度、颜色、圆角、分隔线和底栏遮挡。
- 验证鼠标、触控板和键盘操作；图标命中区域不得小于 44 × 44 px。
- 验证 VoiceOver 名称与操作结果播报。
- 验证深色、系统主题、增加对比度、降低透明度和减少动态效果。
- 验证弹出窗口模式在更宽视口下不会把 480 px 布局机械拉伸；内容宽度继续受现有最大宽度约束。

## 11. 实施顺序

1. 统一浅色/深色 tokens、表面、分隔线、44 px 命中区域和动效基础。
2. 落地保险库主页、自动填充建议和搜索切换行为，作为连续列表范式。
3. 迁移普通列表、搜索结果和条目详情。
4. 迁移设置、外观和生成器。
5. 收敛登录、环境菜单和 Sheet。
6. 完成全状态视觉回归、可访问性检查和交互回归。

每一步必须保留现有业务测试；视觉重构不得通过删除安全确认、错误反馈或字段能力判断来换取简洁。
