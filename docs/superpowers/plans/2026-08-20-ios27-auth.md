# iOS 27 Authentication and Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give login, challenge, hint, lock, and account-switcher routes one compact Auth shell and action hierarchy while preserving every authentication/security boundary.

**Architecture:** Auth route owners and adapters remain unchanged. Real retained templates gain shared form/row roles through their existing per-family transform files and manifests; `global.css` supplies geometry. The common Header remains the sole Back owner on secondary Auth routes.

**Tech Stack:** Angular reactive forms, retained Auth overlays, Vitest, CSS tokens, exact auth guards/manifests.

**Spec:** `docs/superpowers/specs/2026-08-20-ios27-full-ui-harmonization-design.md`

## Global Constraints

- Routes: `/login`, `/lock`, `/2fa`, `/new-device-verification`, `/hint`, `/account-switcher`.
- Inputs paint 40/36px inside 44px owners; one filled primary action; alternative actions are flat 44px rows.
- Header Back is unique on 2FA/new-device/hint; do not add content-level Back.
- Preserve email/password validation, environment menu/Sheet, challenge cancel/expiry/paste, lock methods, PIN/Touch ID, logout, account selection, and focus restoration.
- Menus, self-hosted Sheet, permission Sheet, and logout confirmation retain shaped material.
- Each task updates only the transform and manifest paths named in its **Files** list; login,
  challenge, lock, and account-switcher authority pins remain unchanged.
