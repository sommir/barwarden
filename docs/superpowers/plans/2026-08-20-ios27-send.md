# iOS 27 Send Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Send list, add/edit/read-only forms, and created confirmation share the compact row/form grammar without changing mutation, policy, stale, or confirmation ownership.

**Architecture:** Local route components remain command owners. Send list/list-item/created HTML stay static transforms; their TypeScript and form/detail/options presentation use the existing bounded patch pipeline. Shared roles provide geometry; the Send manifest remains exact and byte-reproducible.

**Tech Stack:** Angular, retained Send overlays, Vitest, CSS tokens, patch/manifest updater.

**Spec:** `docs/superpowers/specs/2026-08-20-ios27-full-ui-harmonization-design.md`

## Global Constraints

- Routes: `/tabs/send`, `/add-send`, `/edit-send`, `/send-created`.
- List rows are 48/44px; New/Search/Filter/View/Copy/More owners are 44px with 32/28px plates.
- Forms use 40/36px controls, 12/10px gaps, 72px textarea minimum, one filled Save.
- Preserve dirty confirmation, pending, validation, first-error focus, password policy, hide-email, expiry/access count, stale outcomes, retry, delete Sheet, and focus restoration.
- Created link must be readable without clipping; Copy is the sole primary and Close is secondary.
- Send list/list-item/created HTML remain static transforms in `official-send-member-transforms.ts`; do not create new HTML patches.
- Run `npm run update:official-send-manifest` twice and keep authority pins unchanged.
